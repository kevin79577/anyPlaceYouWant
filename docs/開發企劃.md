# 四國旅遊實況探索平台｜開發企劃 v0.1

更新日期：2026-11-12。本文為討論初稿；候選來源、數量與工期不代表已完成驗證或採購。

## 1. 已確認方向

- 目標使用者：透過世界各地實況尋找旅遊靈感的人。
- 首波國家：日本、韓國、台灣、泰國。
- 核心價值：透過現場影像與近期景點社群分享，發現想去的地方。
- 體驗要求：高質感、互動流暢，桌面與手機皆可使用。
- 近期貼文是參考資訊，不能標示成即時現場。

## 2. 核心流程

看見精選畫面 → 探索目的地 → 觀看現場／近期分享 → 探索附近 → 收藏想去的地方。

首頁不要求使用者先輸入目的地；搜尋、國家與場景篩選是並行入口。
招牌功能「帶我去一個地方」從已審核且可用的內容抽選，排除本次已看過的地點；無其他候選時明確提示。

## 4. 首批內容目標（暫定）

每國先驗證 2 個目的地，共 8 個；每國至少有 2 個經驗證的現場來源，優先讓每個目的地有 1 個來源及替補。
以 16 個現場來源、每目的地 3～5 筆近 30 天社群分享為收集目標，不以湊數犧牲可信度。
無近期貼文時呈現空狀態；無直播但有近期分享的目的地可以收錄，入口須標示內容類型。
四國都必須有可驗證的現場內容，才可宣稱四國實況版本完成。

## 5. 內容取得

- 現場：原始提供者、官方嵌入播放器或經確認可使用的資料服務。
- 社群：可用的官方 API 搜尋、人工精選、授權創作者內容、原平台搜尋入口。
- 平台搜尋入口不算站內已收錄貼文，不計入近期貼文數量。
- 不承諾搜尋所有平台或完整涵蓋公開貼文；明示目前來源範圍。
- API 憑證置於後端，按平台規定快取、更新及刪除資料。
- 天氣資料需標示來源與資料時間；模型資料不能標成攝影機現場量測。

## 6. 系統方向（待技術驗證）

- 網站：Next.js、TypeScript；繁體中文介面，目的地預留多語別名。
- 後端：目的地、鏡頭、社群項目、審核與回報資料；供應商尚未選定。
- 播放：原平台播放器，選取後載入；一次僅播放一個主要影片。
- 地圖：先比較涵蓋、使用條件與預估流量成本，再選服務。
- 排程：依供應商配額檢查狀態與更新內容，播放成功與真實直播狀態分開記錄。
- 維運：管理介面需驗證身分；公開回報需節流；來源網址需限制合法協定與支援平台。

## 7. 分階段交付

| 階段 | 工作 | 完成門檻 |

| 1 | 產品方向 | 已確認受眾、四國、雙內容主軸 |

先前提出的約 4～6 週為小型團隊粗估；待來源、服務方案與人力確認後重新估時，不含外部審核等待。

## 8. 驗證與觀察

- 任務測試：首次使用者能在 30 秒內找到一個想看的目的地並打開內容（目標，待實測）。
- 功能驗證：搜尋、切換、日期篩選、收藏重開、失效備援、來源連結與管理停用。
- 內容驗證：所有上線項目都有來源與審核紀錄；日期未知不偽造；測試資料不冒充真實內容。
- 裝置驗證：手機／桌面；鍵盤操作、焦點、減少動態偏好；播放器不可用時有出口。
- 觀察指標：開始觀看率、繼續探索率、收藏率、播放失敗率；先建立基準再設 KPI。
